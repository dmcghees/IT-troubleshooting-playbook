# Technical Support Escalation Guide

## Purpose

Not every technical issue should be solved at the first level of support.

This guide outlines when an issue should be escalated and what information should be provided so the next support person can continue troubleshooting efficiently.

## When to Escalate

Escalation may be appropriate when:

* Administrative or elevated access is required
* The issue affects multiple users
* Standard troubleshooting does not resolve the problem
* Network infrastructure may be involved
* Hardware appears damaged or has failed
* Security or suspicious activity is involved
* User permissions need to be changed
* Data may be missing or corrupted
* A third party vendor must investigate
* The issue is outside the support person's authorized scope

## Before Escalating

Complete reasonable basic troubleshooting first when appropriate.

Confirm:

* What the user is experiencing
* Which device, application, or system is affected
* Whether the problem affects one user or multiple users
* When the issue started
* Which troubleshooting steps have already been attempted
* What happened after each step

Avoid repeatedly testing the same action if it is not producing new information.

## Information to Include

A strong escalation should include:

* Clear description of the problem
* User or department affected
* Device or system involved
* Exact error messages when available
* Troubleshooting steps completed
* Results of those troubleshooting steps
* Number of users affected
* Urgency or business impact
* Relevant screenshots or logs when appropriate and permitted

## Example Escalation

**Issue:** Multiple users unable to connect to workplace WiFi.

**Scope:** Four users in the same office area are affected.

**Troubleshooting completed:** Confirmed WiFi was enabled, verified the correct network, restarted affected devices, and tested multiple users and devices.

**Result:** Devices continue to show a connection failure.

**Business impact:** Employees in the affected area cannot access network based workplace applications.

**Next step:** Escalated to network support to review the wireless access point and network infrastructure.

## Security Related Escalation

Security concerns should be handled according to company procedures.

Examples may include:

* Unexpected multi factor authentication requests
* Suspicious login notifications
* Possible phishing messages
* Lost or stolen company devices
* Malware warnings
* Unauthorized access attempts

Do not attempt to bypass security controls in order to resolve an issue.

## Vendor Escalation

Some issues may require support from an outside vendor.

When contacting a vendor, provide:

* Product or service involved
* Clear description of the issue
* Error messages
* Troubleshooting already completed
* Business impact
* Contact information for follow up

Avoid sharing confidential company or user information unless it is required and authorized.

## Following Up

After escalation:

1. Document who the issue was escalated to.
2. Record any ticket or reference number.
3. Update the user when appropriate.
4. Record the final resolution.
5. Add useful findings to internal documentation if the issue may happen again.

## Key Takeaway

Good escalation is not simply passing a problem to someone else. It means providing enough accurate information for the next person to continue troubleshooting without starting over.
